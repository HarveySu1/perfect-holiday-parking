P0答辩前必改（3 条）

P0-1　导航指引 13 步、塞进 130px 框，且不随行走自动滚动
buildInstructions() L2138 · renderGuide() L1764 · updateGuideIdx() L1776 · planRoute() L2156
现象：一条同层直线距离的车位路线被切成 13 步（起点 / 直行 / 左转 / 直行 / 右转 … / 到达），指引内容 351px 装进 130px 的框；实测把当前步设到第 5、9、12 步时，三步全部落在可视区外（liTop 138 / 241 / 319px，框高仅 130px），scrollTop 恒为 0。
根因：A* 在 2m 栅格上只走四邻域，路径呈阶梯状锯齿；buildInstructions 每次"方向改变"就生成一步，锯齿越多步数越多，还保留了 <1m 的"直行 0 米"级碎片。指引框只做了限高，没有跟随滚动。
改法（两步，缺一不可）：
  • 路径先简化再生成指令：共线合并 + 丢弃 <3m 的碎片段，13 步 → 4~5 步；
  • 渲染后把当前步滚进视野。
// ① 共线合并（插在 planRoute 里 cells→meters 之后）
function simplifyPath(m){
  if(!m||m.length<3) return m;
  var out=[m[0]];
  for(var i=1;i<m.length-1;i++){
    var a=out[out.length-1], b=m[i], c=m[i+1];
    var cross=(b.x-a.x)*(c.y-a.y)-(b.y-a.y)*(c.x-a.x);
    if(Math.abs(cross)>1e-6) out.push(b);      // 只保留真正拐点
  }
  out.push(m[m.length-1]); return out;
}
// planRoute:  var meters = simplifyPath(cells.map(...));
// buildInstructions:  if (d > 0)  →  if (Math.round(d) >= 3)   // 丢掉 0~2m 的碎片

// ② 当前步滚进视野（renderGuide 末尾）
var curEl = gb.querySelector('li.cur');
if (curEl) curEl.scrollIntoView({ block:'nearest' });   // 找车页 overflow:hidden，不会带跑页面
P0-2　导航时底部浮层吃掉 55% 的地图，可视地图只剩 161px
.float-panel L186 · .guide L193 / 补丁 L370 · #page-find L471-477

P0-3　无目标时，底部按钮浮层压在"空状态"之上，两套指令互相打架
#mapEmpty L466 (z-index:5) · .float-panel L186 (z-index:20) · updateFindHeader() L1786
现象：没有在停记录也没选目标时，地图中央显示"🔍 输入车牌号，或扫码定位开始寻车 + 手动记录车位按钮"，但上层仍悬浮着"📍 我在哪 / 🧭 开始导航（灰）"，两者矩形重叠。且"开始导航"被禁用却没有任何原因说明，评委点一下只会得到一句 toast。

问题说明与改法
平面图页楼层列语义错假日广场只有 UG 一层，楼层列仍显示"总览 + B1(实际改成 UG)"。建议楼层列按商场动态生成按钮，标题写真实层名，避免出现"总览"但只有一层可选。
平面图底部提示条常驻.lot-tip 占 33px 且常驻（实测 33.6px），与复位按钮、2D 徽标同处底部。建议 3 秒后淡出，或改成右上角"?"图标按需展开。
AI 入口三处重复首页卡 + 目的地 sheet banner + 独立半屏，示例 chip 写了两遍。建议保留"首页入口 + 独立半屏"，sheet 内 banner 收成一行"🤖 用一句话描述需求 ›"。
无键盘可达性所有可点元素都是 div + onclick，无 <button> / aria-label / focus 态，无法 Tab 操作。建议关键入口改 <button> 并加 :focus-visible 描边。

弹窗定位用魔法数字.popup bottom:110px、各 z-index 分散（90/99/110/120/200）。建议统一"bottom 锚点 + 层级表"（mask 90 / sheet 100 / popup 110 / lightbox 120 / toast 200），避免多弹窗叠加时互相遮挡。

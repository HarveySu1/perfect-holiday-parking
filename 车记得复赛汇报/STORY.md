# STORY.md｜车记得 · 复赛汇报

## ① 用户意图对齐

- **目标受众**：完美金鹰·假日商圈 AI 大赛复赛书面评审评委（读稿不路演）。审核五维：真实问题 / AI 实际应用 / 创新性 / 完成度 / 金鹰商圈落地可能性。
- **核心目标**：讲完后评委相信——① 痛点真实（深圳三场头部停车场实地实证，无人做"停车前选车位"）；② 车记得不是新建第 4 个停车 App，而是给主办方已有系统补一层决策服务，三个增量全部复用已有能力；③ AI 用在"理解人话 / 兜底录入 / 解释理由"三层，实时决策走确定性算法是工程判断；④ 一期石岐万象汇灰度、可观测、可回退，零硬件零系统改造；⑤ 架构上绕开车牌敏感信息。记住一句话：「让已有的能力真正被用起来，而不是再盖一栋楼。」
- **PPT 长度**：12 页 = 9 主页（P1–P9）+ 3 备份页（B1–B3）。Hero 配额 2–3 页。
- **视觉调性**：简单明了 / 科技蓝 / 工程克制 / 可信赖 / 零装饰噪音。
- **内容边界**：
  - 必讲：三决策痛点、深圳三场实证、三增量与边界、三层 AI 用点、可演 demo、一期灰度三特性、合规架构优势、团队与未来。
  - 不讲：功能①②③ 拆三页（合并 P4）、竞品矩阵进备份、架构细节进备份、结语不单占页。
  - 禁碰：不写「4500 车位」（作者口径未核实）、不写「寻车 8 分钟」（未实测）、不堆「3000 万客流」；「全行业把智能都花在找回车」必须标「基于深圳三场实地调研」；demo 模拟数据必须显式标「非实测」；团队信息不编造（留占位）。

## ② 页面布局骨架

- **页面总数**：12 页。主结构 P1–P9 按听众判断认知序排：值得做吗（P2）→ 真实+有创新吗（P3）→ 怎么做（P4）→ AI 真有用吗（P5）→ 做得出来吗（P6）→ 能落地吗（P7）→ 合规吗（P8）→ 可持续吗（P9）。B1–B3 为备份页（被问再翻）。
- **目录↔章节扉页契约**：本篇**不设 catalog 目录页**（比赛评审场景、9 页主干，目录浪费一页；结构文档已锁定）。无目录声明 → 全篇 `type: section` 扉页数 = 0，契约不触发，编号连续性无从谈起，骨架成立。
- **Hero 页定位**：P1（封面，默认 hero）、P5（AI 主张，全篇认知高潮）、P9（结束页，默认 hero）。占比 3/12 = 25%，落在 20–30% ✓。Hero 间隔：P1→P5 间隔 3 页、P5→P9 间隔 3 页，无相邻 ✓。
- **rhythm 曲线**：P1 peak / P2 valley / P3 peak / P4 valley / P5 peak / P6 valley / P7 peak / P8 valley / P9 peak / B1 valley / B2 transition / B3 valley。无连续 ≥3 页 valley ✓；P7 用三阶段视觉打破 P6/P8 的信息密度沉闷。
- **非对称版式预算**：12 页中 10 页非对称（83% ≥ 40% ✓）。非对称明细：P1 全幅图+骑线文字、P2 左标题+右内容、P3 上大图+下方卡片、P4 非对称双栏、P5 巨型数字+洞察、P6 上大图+下方卡片、P8 非对称双栏、B1 左标题+右内容、B2 上大图+下方卡片、B3 左标题+右内容。
- **对称版式预算**：仅 2 页——P7（N卡片横排，三阶段，全篇唯一 1 次 ≤2 上限）、P9（居中金句，结束页）。其余 10 页全部非对称 ✓。相邻页版式两两不同 ✓（P3 与 P6 同用「上大图+下方卡片」但间隔 2 页，允许）。
- **版式多样性**：`左大图+右侧文字`(0) + `非对称双栏`(P4、P8 = 2) 合计 2 页 ≤ 12×40% = 4.8 ✓。
